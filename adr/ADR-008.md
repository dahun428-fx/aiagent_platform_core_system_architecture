# ADR-008: 사용자·Agent Identity

- Status: Decided
- Baseline: v0.1 / Q8
- Date: 2026-10-30
- Owner / 회사 승인자: TBD
- Source: [기준선](../docs/requirements/baseline-v0.1.md), [출처](../sources/README.md)

## Context
Credential Broker를 Agent Identity에 두고 최소 권한과 감사성을 확보한다.

## Decision
플랫폼은 다음 결정을 준수해야 한다(MUST): 사용자 및 Agent/workload 신원, 위임 및 독립 실행을 지원한다.
Agent Identity 내부 Credential Broker가 단기·audience 제한 credential을 관리해야 한다(MUST). Runtime/LLM에는 장기 secret을 전달해서는 안 된다(MUST NOT).



## Alternatives considered
공유 서비스 계정만 사용: 공통 기준선과 일치하지 않거나 불필요한 결합을 만든다.
현재 선택은 제품 선정이 아닌 논리 계약의 확정이다.

## Consequences
Credential Broker를 Agent Identity에 두고 최소 권한과 감사성을 확보한다. 어댑터 적합성 및 변경 비용을 운영 주체가 관리해야 한다(SHOULD).
구현 완료 여부는 해당 계약 테스트와 통합 증거로 별도 판단해야 한다(MUST).

## Constraints
회사 환경·제품·운영 수치는 TBD. 예제 값은 production 기본값이 아니다.
[구현 범위](../docs/release-scope.md)를 준수한다(MUST).

## Security impact
tenant·principal·Agent/workload·정책 버전을 경계에서 검증하고 최소 권한을 유지해야 한다(MUST).
감사 로그에는 토큰·secret·원문 개인정보를 기록해서는 안 된다(MUST NOT).

## Supersession / migration

breaking change는 병행 버전·소비자 전환·rollback 증거 없이는 배포하지 않는다.
