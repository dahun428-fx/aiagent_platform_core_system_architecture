# ADR-037: Agent Adapter와 로컬 적합성

- Status: Decided
- Baseline: v0.1 보강 / Q37
- Date: 2026-11-06
- Owner / 회사 승인자: TBD
- Source: [기준선](../docs/requirements/baseline-v0.1.md), [근거와 참고 자료](../docs/onboarding/10-references.md)

## Context
참조 구현은 고정된 `agent-demo` 하나만 실행해, 다른 팀이 자기 Agent를 표준에 맞춰 연결하고 검증할 방법이 없었다.

## Decision
Agent는 `handle(ctx, message) -> output` 하나를 구현하는 adapter로 연결한다. adapter는 플랫폼이 주입하는 `AgentContext`(`generate`, `call_tool`, `log`)만 사용하며, Identity·정책·자격증명·플랫폼 객체를 받지 않는다. 실행 대상은 Manifest의 `runtime.adapter = python-inprocess-v1`과 `runtime.entrypoint = module:factory`로 정하고, 로컬 Registry는 `deployment.profile = local`만 받는다. Manifest의 `identity.requiredScopes`는 호출자가 모두 보유해야 adapter를 실행하고, `identity.mode = independent`는 사용자 principal 없는 Agent workload 신원(requiredScopes와 정책의 교집합)으로 실행한다. 적합성은 `agentctl conformance`의 11개 검사로 판정하며 모든 판정은 플랫폼 경계에서 수행한다. 검사 결과는 manifest-loading·adapter-path·platform-enforcement로 구분하고, 업무 품질·보안·프로덕션 인증이 아님을 출력에 명시한다. Manifest의 Agent 유형에 `message`를 추가하고 계약 0.1.1로 동결한다.

## Alternatives considered
새 adapter 입출력 스키마 추가: 기존 invocation `input`·result `output`과 같아 중복이다. 원격(HTTP) adapter 우선: 첫 단계의 범위가 커진다. 후속으로 둔다.

## Consequences
in-process 로딩은 격리 경계가 아니다. 로딩된 코드는 같은 프로세스의 내부 객체에 접근할 수 있으므로 이 방식은 로컬 학습·적합성 확인 전용이며, 신뢰하지 않는 코드에 사용해서는 안 된다(MUST NOT). 격리가 필요한 실행은 후속 원격 adapter로 제공한다.
adapter는 전역 잠금 안에서 실행되며 `timeoutMs`는 적용되지 않는다(mock 한계).
구현 완료 여부는 해당 계약 테스트와 통합 증거로 별도 판단해야 한다(MUST).

## Constraints

## Security impact
tenant·principal·Agent/workload·정책 버전을 경계에서 검증하고 최소 권한을 유지해야 한다(MUST).
감사 로그에는 토큰·secret·원문 개인정보를 기록해서는 안 된다(MUST NOT).
adapter 예외의 메시지와 스택은 응답에 포함하지 않는다(MUST NOT).

## Supersession / migration
계약 0.1.0과의 차이는 `capabilities.type`의 `message` 추가뿐이다. 원격 adapter를 추가할 때 새 ADR에서 이 결정을 확장한다.
