# ADR-032: Memory

- Status: Decided
- Baseline: v0.1 보강 / Q32
- Date: 2026-11-06
- Owner / 회사 승인자: TBD
- Source: [기준선](../docs/requirements/baseline-v0.1.md), [근거와 참고 자료](../docs/onboarding/10-references.md)

## Context
대화·작업 사이 정보 유지 요구가 Durable checkpoint와 섞이면 범위·보존 규칙이 흐려진다.

## Decision
Memory를 Agent Runtime 하위 구성요소로 둔다. 단기·장기 Memory를 구분하고, 모든 항목을 tenant·주체·Agent에 결합하며, 비신뢰 데이터로 취급하고, 시크릿·자격증명 저장을 금지한다.

## Alternatives considered
Memory를 별도 Core System으로 분리: 실행 맥락과 분리되어 범위 검증이 어려워진다.

## Consequences
v0.1은 규칙만 정의하고 저장소·API는 제공하지 않는다(목표 규칙). 구현 상태는 core-systems.md의 상태표를 따른다.
구현 완료 여부는 해당 계약 테스트와 통합 증거로 별도 판단해야 한다(MUST).

## Constraints
회사 환경·제품·운영 수치는 TBD. 예제 값은 production 기본값이 아니다.

## Related contracts / verification
[Memory](../docs/memory.md) · [Core Systems 구현 상태](../docs/core-systems.md#구현-상태)

## Security impact
tenant·principal·Agent/workload·정책 버전을 경계에서 검증하고 최소 권한을 유지해야 한다(MUST).
감사 로그에는 토큰·secret·원문 개인정보를 기록해서는 안 된다(MUST NOT).

## Supersession / migration
Memory 계약 추가 시 Manifest 확장과 함께 새 계약 버전으로 도입한다.
