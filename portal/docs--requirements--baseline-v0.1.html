요구사항 기준선 v0.1

상태: Decided (아키텍처 결정). 회사의 공식 승인·production 배포 승인을 대신하지 않는다. 기준일: 2026-10-30 (Asia/Seoul). 버전: 0.1.0.

출처와 정정

두 첨부 Deep Research 보고서의 Q1–30 표 및 검증 결과를 기준으로 한다. 원 Q&A 원문은 대화 도구가 content-reference로만 반환하여 직접 대조하지 못했다. 따라서 아래 한국어는 질문 원문 인용이 아닌 결정의 규범적 정리다. Q30은 검증 보고서 및 현재 사용자 지시에 따라 명시적 B 선택으로 정정한다. 회사 환경·제품·수치는 TBD이며 예제 fixture 수치는 합성 테스트 값이다.

v0.1 보강 결정 (2026-11-06)

Q1–Q30 이후 Core Systems 정합화를 위해 추가로 확정한 결정이다. 구현 상태는 Core Systems 구현 상태를 따른다.

Q 결정 기준선 ADR 추적
Q31 Core Systems 명칭과 경계 MUST: 플랫폼은 AI Platform Applications, Agent Platform APIs, Agent Factory, Agent Runtime, Agent Tools, Agent Identity, Agent Observability, Agent Evaluation, Agent Gateway, Agent Tuning의 10개 Core System으로 구성한다. ADR-031 Core Systems
Q32 Memory MUST: Memory를 Agent Runtime 하위 구성요소로 둔다. ADR-032 Memory
Q33 Guardrails MUST: Guardrail은 공통 검사 서비스와 네 집행 지점(Agent Gateway 모델 경로의 모델 입출력, 도구 경로의 도구 호출·결과, RAG 검색 결과, Agent Runtime의 실행 제어)으로 구성한다. ADR-033 Guardrails
Q34 Observability 규격 MUST: 실행 추적은 W3C Trace Context로 전파하고, span 이름과 속성은 OpenTelemetry GenAI semantic conventions를 따른다. ADR-034 Observability
Q35 Evaluation과 Agent Tuning MUST: Evaluation은 배포 전 평가·실행 추적 분석·운영 모니터링 3단계로 수행하고, 위험도 high Agent는 red teaming을 포함한다. ADR-035 Evaluation, Agent Tuning
Q37 Agent Adapter와 로컬 적합성 MUST: Agent는 AgentContext만 사용하는 adapter로 연결하고, 로컬 Registry와 9개 적합성 검사로 검증한다. ADR-037 Core Systems
Q36 Agent Card MUST: A2A 프로토콜을 채택하거나 Agent를 다른 팀·외부에 노출할 때, Registry가 Manifest와 등록 정보에서 A2A 1.0.0 Agent Card를 생성하고 조직 키로 JWS(JCS 정규화) 서명해 발행한다. ADR-036 Agent Card
