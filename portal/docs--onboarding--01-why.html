플랫폼 도입 배경과 설계 원칙

개발자 가이드 문서입니다. 규범(MUST/SHOULD)은 링크된 기술 표준 문서가 기준이며, 이 가이드와 다를 경우 기술 표준 문서를 따릅니다.

주요 용어 AI Agent 신뢰 경계 기술 계약 TBD 인증 / 인가 시크릿 / 자격증명

학습 목표

  • 팀별 Agent 개발에서 반복되는 보안·운영 과제를 설명할 수 있습니다.
  • 팀별 개발 환경과 전사 공통 통제의 책임 구분을 설명할 수 있습니다.
  • 플랫폼의 제공 범위와 제공하지 않는 범위를 구분할 수 있습니다.

배경

문제 정의 Agent를 개발하는 팀이 늘어나면, 각 팀이 인증·데이터 반출·시크릿 관리·실행 추적을 개별적으로 구현하게 됩니다.

현황 팀마다 구현 방식과 보안 수준이 다르면 전사 보안 수준은 가장 약한 구현에 맞춰지고, 동일한 기능이 중복으로 개발됩니다.

설계 방향 이러한 통제를 공통 제어·연계 지점에서 일괄 적용합니다. Agent 개발은 각 팀의 방식대로 진행하고, 통제는 플랫폼이 담당합니다.

팀별 개발 시 반복되는 과제

인증·인가

인증(Authentication, 호출 주체 확인)과 인가(Authorization, 접근 권한 판단)가 팀마다 다르게 구현됩니다.

데이터 반출 통제

기밀 데이터가 외부 모델로 전송되지 않는다는 보장이 없습니다.

시크릿·자격증명 관리

시크릿(Secret)과 ERP·메일·저장소 접근 자격증명(Credential)이 코드나 설정 파일에 남습니다.

실행 추적

요청이 거친 구성요소와 수행한 작업을 종단 간으로 추적하기 어렵습니다.

품질 검증

업무 적용 여부를 판단할 공통 평가 기준이 없습니다.

영향

개발 비용이 중복되고, 단일 팀의 보안 결함이 전사 위험으로 확대됩니다.

핵심 설계 원칙

핵심 설계 원칙 Agent 개발에는 팀별 도구와 프레임워크를 사용하며, 플랫폼은 공통 제어·연계 지점에서 인증·인가, 정책 적용, 관측성(Observability), 평가 및 배포 통제를 수행합니다.

소스 코드는 각 팀의 Git 저장소에서 관리하고, 개발은 각자의 IDE와 CLI에서 수행합니다. 플랫폼이 요구하는 것은 다음 네 가지 기술 계약 준수입니다.

  1. Manifest 제출Agent의 메타데이터, 런타임 설정, 권한 요구사항을 선언
  2. Agent Platform APIs 진입Agent 호출은 Agent Platform APIs로 수행
  3. Agent Gateway 경유외부 모델·도구 호출은 Agent Gateway를 통해 수행
  4. 추적 컨텍스트 전파trace 정보를 모든 구간에 전달

제공 범위

플랫폼이 제공하지 않는 것

  • 모든 Agent를 단일 중앙 서버에서 실행하는 구조
  • 특정 프레임워크(LangGraph 등)의 강제
  • 특정 IdP·CI·벡터 DB 제품의 지정
  • 소스 코드 업로드가 필요한 Agent Studio

플랫폼이 제공하는 것

  • 개발자 PC·사내 서버·클라우드에서 동일한 계약에 따른 실행
  • 공통 Runtime 계약과 framework adapter 기반의 프레임워크 선택
  • 회사 결정이 필요한 제품·수치의 TBD 분리
  • 불변 버전 참조와 검증 근거의 중앙 등록

패키지 구성

기술 표준 문서

아키텍처, 신뢰 경계, 운영 규칙을 정의한 한국어 문서

API 계약과 JSON Schema

OpenAPI와 JSON Schema로 작성된 기계 판독 가능한 계약

예제 구현

4종 Agent Manifest, Python mock, TypeScript 클라이언트, 테스트

이 패키지는 구현 착수를 위한 기술 표준이며, 회사 IdP나 실제 실행 환경에 연결된 프로덕션 시스템이 아닙니다.

이해도 점검

Q1. 플랫폼을 사용하려면 개발 프레임워크를 변경해야 합니까?

아닙니다. 공통 Runtime 계약과 framework adapter로 연결하므로 프레임워크는 각 팀이 선택합니다.

Q2. 플랫폼의 공통 제어 지점이 담당하는 것은 실행입니까, 통제입니까?

통제입니다. 실행은 여러 환경에 분산되며, 인증·인가, 정책, 관측성, 평가, 배포 통제를 공통 지점에서 적용합니다.

요약

  • 팀별로 구현하던 인증·인가, 데이터 반출 통제, 시크릿 관리, 실행 추적, 품질 검증을 공통 지점에서 수행합니다.
  • 개발 방식은 유지하고, Manifest 제출·Agent Platform APIs 진입·Agent Gateway 경유·추적 컨텍스트 전파라는 기술 계약을 준수합니다.
  • 이 책임은 10개 Core System이 나눠 맡습니다. 구성은 다음 장에서 설명합니다.
  • 결정되지 않은 제품과 수치는 TBD로 유지하며 임의로 정하지 않습니다.
