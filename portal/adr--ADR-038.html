ADR-038: upstream 실패 구분, deadline 전달, 도구 경로 202 (계약 0.2.0)

  • Status: Decided
  • Baseline: 구현 로드맵 C1
  • Date: 2026-11-11
  • Owner / 회사 승인자: TBD
  • Source: 구현 로드맵, 계약 버전·호환성

Context

계약 0.1.1은 upstream 실패를 모두 503 UPSTREAM_UNAVAILABLE 하나로 표현한다. 호출자는 응답이 늦었는지, upstream이 잘못 답했는지, 지금 연결할 곳이 없는지 구분할 수 없어 재시도 여부를 정할 수 없다. 한도 초과(429)에는 전용 오류 코드도, 언제 다시 시도할지도 없다. 서비스 사이에 남은 시간을 넘기는 방법이 없어 hop마다 자기 timeout을 따로 적용한다. 같은 Idempotency-Key의 도구 호출이 아직 실행 중일 때 돌려줄 응답도 없다. 구현 조각 S2(timeout), S3(오류 매핑), S4(rate limit), S6b(동시 실행)는 이 계약이 있어야 시작할 수 있다.

Decision

계약을 0.2.0으로 개정한다. 상태 코드마다 오류 코드 하나를 정한다.

상황 상태 code 헤더
upstream이 시간 안에 답하지 않음 504 UPSTREAM_TIMEOUT
upstream이 5xx나 계약에 맞지 않는 응답을 줌 502 UPSTREAM_ERROR
연결할 upstream이 없음(연결 거부, circuit open, 허용된 경로 없음) 503 UPSTREAM_UNAVAILABLE Retry-After(선택)
tenant·Agent 한도 초과 429 RATE_LIMITED Retry-After(선택)
  • health를 뺀 모든 operation에 502·504 응답을 추가한다.
  • Retry-After는 0 이상의 정수 초(delta-seconds)만 쓴다. HTTP-date 형식은 쓰지 않는다.
  • health를 뺀 모든 operation에 선택 헤더 Request-Timeout-Ms(1 이상의 정수)를 추가한다. 값은 호출자에게 남은 시간이다. 받는 쪽은 이 값과 자기 timeoutMs 중 짧은 쪽을 적용하고, 다음 hop에는 그동안 쓴 시간을 뺀 값을 보낸다.
  • invokeTool에 202 응답을 추가한다. 같은 Idempotency-Key 요청이 아직 실행 중이라는 뜻이며, 본문 없이 Retry-After와 traceparent만 돌려준다. 도구는 다시 실행하지 않는다.
  • 모든 OpenAPI 문서의 info.version을 0.2.0으로 올리고, 429·503 예시의 code를 실제 의미(RATE_LIMITED, UPSTREAM_UNAVAILABLE)로 고친다.

Alternatives considered

절대 시각 deadline 헤더(예: RFC 3339 시각): 서비스 사이 시계 차이만큼 deadline이 틀어진다. 남은 시간(ms)을 넘기는 방식을 택했다. 502·504 대신 503 하나에 세부 code만 추가: 프록시·로드밸런서·HTTP 클라이언트가 상태 코드만 보고 재시도를 정하므로 상태 코드부터 구분한다. 도구 202에 실행 상태 본문 추가: 지금은 "아직 실행 중" 한 가지뿐이라 본문이 필요 없다. 상태가 늘어나면 새 ADR에서 정한다.

Consequences

기존 응답·파라미터·오류 코드는 그대로 두고 더하기만 했다(tests/test_contracts.py의 test_0_2_0_only_adds_to_0_1_1). 그러나 problem.code를 닫힌 enum으로 검증하는 0.1.x 소비자는 새 코드를 받으면 실패한다. 이런 소비자는 0.2.0 스키마로 갱신하거나, 모르는 code를 상태 코드 기준으로 처리해야 한다(MUST). 참조 구현과 impl/는 아직 새 응답을 보내지 않는다. S2~S4, S6b 조각이 차례로 보내기 시작한다.

Constraints

timeout·재시도 수치, rate limit 한도는 회사 환경에서 정한다(TBD). 예제 값은 production 기본값이 아니다.

Related contracts / verification

problem.schema.json · model-gateway.openapi.json · tool-gateway.openapi.json · contracts/released/0.2.0.json · 계약 테스트

Security impact

502·504 응답의 detail에 upstream 주소, 내부 호스트 이름, upstream 원문 오류를 넣어서는 안 된다(MUST NOT). Request-Timeout-Ms는 호출자가 보낸 값이므로 받는 쪽의 timeoutMs보다 길게 적용해서는 안 된다(MUST NOT). 값이 매우 커도 자기 상한을 넘기지 않는다. 202는 실행 중이라는 사실만 알리며, 다른 principal의 같은 key 요청에 결과나 상태를 보여 주지 않는다(MUST NOT).

Supersession / migration

0.1.1 대비 변경은 위 Decision 표와 목록이 전부다. 소비자 전환 순서는 계약 버전·호환성을 따른다.
