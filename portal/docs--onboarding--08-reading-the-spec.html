자주 묻는 질문

내 Agent를 플랫폼에 올리려면 소스를 어디에 업로드하나요?

업로드하지 않습니다. 소스는 팀 저장소에 두고, Registry에는 불변 revision, artifact digest, Manifest, 평가 증거를 등록합니다.

LangGraph를 쓰고 있는데 바꿔야 하나요?

아닙니다. 공통 Runtime 계약과 framework adapter로 연결합니다. Manifest의 runtime.framework와 runtime.adapter에 적으면 됩니다.

외부 모델을 코드에서 바로 불러도 되나요?

production에서는 특정 공급사에 직접 묶지 않고 Model Gateway를 거쳐야 합니다. 그래야 데이터 분류에 따라 외부 전송을 막고, 공급사를 바꿔도 Agent 코드를 고칠 필요가 없습니다. 처음부터 Model Gateway 계약에 맞춰 개발해 두면 승격할 때 고칠 것이 줄어듭니다.

MCP 서버를 Agent가 직접 붙어 쓰면 안 되나요?

기본 패턴은 Tool Gateway의 adapter가 MCP client를 소유하는 enterprise proxy입니다. MCP는 도구 프로토콜일 뿐 회사 권한 정책을 대신하지 않습니다. tools/list에는 허용된 도구만 보이고, tools/call도 같은 권한·입출력·감사 규칙을 따릅니다.

도구 API 키는 어디에 넣나요?

Agent 코드, Manifest, 환경 변수 어디에도 넣지 않습니다. Credential Broker가 호출마다 짧은 수명의 자격증명을 발급하고, Tool Gateway의 adapter 안에서만 씁니다.

개발용 Mac mini를 등록했는데 바로 서비스에 쓰면 되나요?

안 됩니다. 등록(registered)과 production 승인(production-approved)은 다릅니다. production에는 보안, 평가, 복구, 위험별 SLO 증거가 필요합니다.

예제에 TTL이나 포트 같은 숫자가 있는데 그대로 쓰면 되나요?

안 됩니다. 예제의 주소, TTL, 깊이, 평가 점수는 합성 값입니다. 회사 수치는 TBD 등록부에서 정해집니다.

이 패키지로 바로 production을 운영할 수 있나요?

아닙니다. 이 패키지는 구현을 시작하기 위한 기술 표준입니다. 회사 IdP, 정책 엔진, 비밀 관리, 실행 환경을 연결하고 운영 검증을 거쳐야 합니다. 시작 순서는 CI 통합에 있습니다.
